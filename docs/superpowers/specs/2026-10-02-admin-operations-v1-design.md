# Coursmith 管理员运营后台与交付管理 v1 设计规格

日期：2026-10-02。状态：用户已确认本批规格、实施计划及分任务实现/逐项独立审查方式；2026-10-02 在隔离 worktree 开始实施。

关联路线：`docs/roadmaps/2026-10-02-coursmith-next-stage-roadmap.md`。

## 1. 本批目标

项目所有者可登录内部网页后台，为现有可交付课程设置商品信息和授权政策、记录第三方店铺订单、生成单个或批量兑换码，并完成补发、访问恢复、暂停销售和学习权益撤销。买家无需理解 HTML 或安装软件；会话过期/换设备后仍可恢复同一份学习权益和进度。

用户已确认：后台先由一人使用，预留多人扩展。所有写入记录 `actor_admin_id`，账号表保留 `role=owner`；首版没有邀请成员或配置权限页面。

本批不建设新的 AI 制作工作台和内容版本发布系统。导航保留清晰阶段说明，但不展示虚假的“已可用”按钮。现有课程可绑定商品；新商品草稿可编辑，只有绑定已校验内容并完成销售检查后才能发码。资料制作在后续 M2、M3 合拢。

## 2. 业务对象

| 对象 | 含义 | 生命周期与约束 |
| --- | --- | --- |
| 课程 | 正文内容资产，沿用现有 `course_id` 和课程 URL | 不因商品暂停销售而删除 |
| 商品 | 标题、分类、文案、店铺链接、交付政策、课程绑定 | `draft → active → paused → active`；归档仅限不再销售，仍保留历史 |
| 订单记录 | 管理员手工登记并在店铺核验的成交 | 首版一条记录绑定一个商品、一份权益；不表示站内收款 |
| 码批次 | 一次生成的码集合，含用途和政策快照 | 明文一次提供；支持按未使用状态批量作废 |
| 激活码 | 单次领取一门课程权益的凭证 | `unused → redeemed` 或 `unused → revoked`；到期状态按时间计算 |
| 学习权益 | 授权对象、访问期限和未来升级政策快照 | `active → revoked` 或到期；不绑定某一个浏览器 |
| 学习凭证 | 买家重建设备会话的个人凭证 | 只存哈希；可由管理员重置；与激活码是不同凭证 |
| 设备会话 | 一次浏览器访问授权 | 沿用 72 小时有效期；最多三个有效会话；不承担购买权益保存 |
| 进度 | 一份权益对某章节的完成状态 | 换设备、恢复凭证、会话到期不删除 |

第一批只支持一商品对应一课程。商品分类可配置中文名称和安全 slug，不限定行业或人群。商品可绑定现有 published 课程，但技术状态 `published` 不自动证明其可售质量。

## 3. 商品管理与准备

`/admin/products`：按分类、状态、标题筛选，分页默认每页 20 项。详情页包含基础信息、交付政策、课程检查、销售渠道、近期订单和发码记录。

可编辑字段：

- 商品标题、分类、简介、适合人群、先修条件、可验证的成果目标。
- 绑定课程、课程版本、AI 辅助生成说明、售后说明。
- 淘宝/闲鱼等渠道的店铺名称和商品链接，链接仅允许 HTTPS。
- 在线访问；是否提供 PDF；是否允许提供专业 HTML/ZIP。
- 访问期限：经营者必须选定 1–3650 天或“无固定到期日”，不提供隐式商业默认值。
- 更新政策：首批固定为“当前版本交付”；可显示后续阶段说明，不宣称已支持自动升级。

`active` 前必须：

1. 绑定一门通过验证的既有课程，快照保存课程 ID、版本和包哈希。
2. 填写成果、适合人群、访问期限、售后说明和交付格式。
3. 管理员确认内容质量、来源/授权、AI 说明、手机试学、所承诺下载文件都已检查。
4. 对提供 PDF/ZIP 的商品确认对应文件可用；文件不存在不得只显示下载按钮。

现有示例课程导入后台后商品默认 `draft`，不自动开启销售。检查记录绑定课程包哈希和商品承诺快照；文件或关键商品字段变化使检查失效，重新确认后才能继续发码。

本批现有正文仍采用 HTML；网页只修改商品展示信息，不改正文、不重排/删除章节。公开详情页改为读取商品实际文案，不继续使用所有课程共用的硬编码学习成果。草稿/归档商品不出现在公开商品列表；暂停商品保留说明和售后入口，隐藏购买入口并停止新码生成。已发码的兑换和有效权益不受上述销售状态影响。

分类维护在后台完成：创建安全 slug 和中文名称、排序、停用空分类；被商品引用的分类只能停用不能直接删除。课程已有分类字符串作为兼容来源，商品使用分类 ID，不为改展示名称而修改课程正文或 ID。

## 4. 激活码与批次

`/admin/code-batches` 展示批次编号、商品、用途、创建者、数量、未使用/已兑换/已作废/已过期数。详情只显示非敏感码编号、状态和关联订单，不重显明文。

创建表单：

- 商品：只允许当前 `active` 且课程检查未失效的商品。
- 数量：整数 1–200，默认 1。
- 用途：成交交付、内部测试、试学赠送。
- 激活有效期：1–365 天，默认 30 天；这是领取期限，不是学习期限。
- 批次备注，最多 1000 字；政策快照自动来自商品。

码由密码学安全随机源生成，新码格式采用 `CS-` 加 24 字节 URL-safe 随机串。数据库存 SHA-256 哈希和单独的非敏感码编号；不记录原始码或把原始码写入日志。

每次生成结果页提供“复制”和“下载 CSV”；浏览器用该次响应里的临时数据生成 CSV，不再请求服务端重显原始码。CSV 包含码编号、原始码、商品、激活截止时间和不含原始码的兑换入口。响应 `Cache-Control: no-store`，不保存服务器端明文 CSV 文件，也不放入浏览器 localStorage。字段防止表格公式注入。

网络中断、刷新或未保存 CSV 后，不可从数据库找回明文。详情说明原因并提供“作废本批未使用码并重新生成”；已兑换项保留权益，不随批次重发一起撤销。不会假装下载成功。

每次表单包含独立幂等键，重复提交不得创建第二批。幂等重放显示已完成批次信息而非原始码；它不绕过一次明文交付约束。单码补发建立 `replacement_for_code_id`，先撤销旧未使用码再生成替代码，作为同一事务。

未使用码的作废按钮与已领取权益的撤销按钮分开。作废时必须输入原因；学习权益撤销见第 6 节。

## 5. 手工订单与发货

`/admin/orders` 支持录入、查询、状态过滤。字段：渠道、店铺标识、订单号、商品、成交金额（人民币分，非负整数）、成交日期、管理员备注、交付状态。无需买家手机号、邮箱或真实姓名。

唯一键为 `(channel, shop_id, external_order_id)`。同一订单记录只对应一个商品/一份权益；多商品订单在本批 UI 中明确为不支持，不伪装拆单。

交付状态通常为 `recorded → code_ready → delivered → activated`；外部已退款标记为 `refunded`。生成绑定码后是 `code_ready`，管理员确认店铺已发货后是 `delivered`。如果买家先兑换，允许 `code_ready → activated`；之后确认发货只补发货时间，不把状态降回 `delivered`。界面始终说明不能自动知道店铺消息是否真正送达。

两种操作：

- 订单发货：录入/确认订单后生成一个绑定订单的激活码，在同一结果页提供码和可复制的发货文案，再确认已发货。
- 无订单批次：内部测试/赠送或经营者在店铺自行发码。后台显示“未关联订单”；若需要补关联，必须核对非敏感码编号和目标订单，写审计记录。

发货文案包含商品名称、网站兑换入口、原始激活码、激活期限、访问期限、格式和店铺售后方式；不夸大“永久有效”，不包含模型配置和内部地址。

录入“已退款”之前管理员须在第三方店铺确认。后台不调用退款接口；保存标记时原未使用码作废，已领取权益及所有其会话撤销，并记录原因。同一交易不能因浏览器重复点击创建重复授权。

金额快照不随以后商品修改而变化；报表只描述手工记录，不与平台结算账目自动对账。

## 6. 买家访问、恢复与售后

### 6.1 首次兑换

1. 买家打开现有 `/access`，选择/自动识别商品并输入激活码。
2. 服务端事务核对商品绑定、码哈希、领取期限、未兑换状态及是否已作废；领取时使用码的授权政策快照，不使用当前商品新政策。
3. 创建一份持久权益、一个 72 小时会话以及 `LK-` 加 32 字节 URL-safe 随机串的个人学习凭证。凭证只存哈希。
4. Cookie 仅保存随机会话标识，保持 HttpOnly、SameSite=Lax、生产 Secure。
5. 兑换结果页一次展示个人学习凭证和“请保存，用于换设备/过期后继续学习”的说明，再提供进入课程按钮。结果页禁止缓存和携带凭证的 URL。

有固定期限的商品从兑换时计算访问到期时间；“无固定到期日”保存空到期时间，但不自动生成超出经营者售后承诺的营销措辞。拒绝并发重复领取，事务只可成功一次。

### 6.2 继续学习

`/access/restore` 接受个人学习凭证并建立同一权益的新会话，进度来自权益而非 Cookie。有效会话最多三个，建立第四个前页面告知“将退出最早登录的设备”，用户确认后撤销最早会话；不通过浏览器指纹识别设备。

课程首页和章节页提供“标记已完成/取消完成”和返回目录/上一章/下一章。页面没有 JS 时表单仍可保存进度；API 保持严格整数/布尔校验。

无效、已撤销、已到期凭证返回通用失败提示和店铺售后入口，不泄露绑定订单号。当前页面的会话即将失效不代表商品到期；提示须区分。

### 6.3 售后重置

经营者在店铺核验订单后，从订单或权益详情选择“重置学习凭证”。执行前显示受影响课程、权益到期时间、将退出的会话数量，要求原因；旧凭证及该权益全部会话失效，新凭证明文一次提供。进度与权益期限保持不变。

找不到明确订单或旧权益时不得凭猜测关联两个用户；先补核验记录。原始凭证丢失且无可信购买证据时，后台不能自动证明归属。

### 6.4 撤销与暂停销售

- 作废未使用码：只影响领取，未创建权益。
- 撤销已领取权益：阻止恢复和所有已有会话访问，保留订单/审核/历史进度。
- 暂停商品销售：阻止新发码，履行既有领取与学习承诺。
- 本批不提供直接删除课程、订单、已使用码和权益功能。

## 7. 管理员认证与请求安全

第一位管理员由部署初始化一次，之后日常操作与密码修改在网页完成。没有默认账号/密码、公开注册或仅靠隐藏路径保护。

- 部署命令 `python -m course_platform.cli init-admin` 交互读取账号和密码，密码不作为命令行参数、不回显；账户写入数据库。
- 密码长度 12–128 字符，使用 `pwdlib[argon2]` 生成 Argon2id 哈希，数据库不存明文。此哈希方案参考 FastAPI 文档，后台使用服务端会话，不照搬教程的 JWT 流程。[FastAPI 密码哈希说明](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/)
- 管理会话采用 32 字节随机 token，只存哈希；Cookie `coursmith_admin`、Path=/admin、HttpOnly、SameSite=Strict、生产 Secure；绝对有效期 8 小时，30 分钟无操作失效。
- 登录成功轮换 token，修改密码/退出撤销管理会话；旧 token 不继续生效。未初始化管理员时后台返回可理解的 503，不开放安装页面。
- 所有后台写操作用 POST，带与会话绑定的 CSRF token；登录表单也有短期预登录 token 和 Origin 校验。GET 不改变状态。
- 管理会话和买家会话各有独立 CSRF token：服务端存其哈希，另设同作用域的 HttpOnly CSRF Cookie，模板从 Cookie 读取并填入表单，提交时恒定时间比较表单、Cookie 和会话哈希。登录预会话 token 有效期 10 分钟；成功登录/恢复时重建 token。公开进度 API 同样要求 CSRF header，不能成为表单保护的旁路。
- 限流状态存数据库。管理员登录按账号和来源各自 15 分钟最多五次失败，临时限制 15 分钟；公开兑换/恢复按来源一分钟最多十次请求。默认仅信任直连来源，转发头只在指定可信代理后采用。
- 后台 JS 从自有 `/static/admin/` 加载，后台 CSP `script-src 'self'` 且无内联脚本；课程正文继续禁止脚本。Jinja 自动转义，禁止把模型原始 HTML 标为可信插入后台布局。
- `/admin`、兑换结果、个人学习凭证、CSV 及授权页面响应禁缓存。静态素材白名单按章节区分，试学不能查看全部付费素材。
- 请求体流式限制：普通表单 64 KiB、进度 JSON 16 KiB；先限制再完整解析。不要读取全部超大请求后才判断长度。
- 日志中不含密码、激活码、学习凭证、会话 token、完整店铺订单号和 API Key；后台审计显示业务 ID 和必要备注。管理员须避免在备注中粘贴敏感凭证。

## 8. 数据结构与迁移

使用现有 SQLite，新增分步迁移记录 `schema_migrations`。本批新增/扩展：

| 表 | 关键数据/约束 |
| --- | --- |
| `admins` | 账号唯一、密码哈希、role、启用状态 |
| `admin_sessions` | token 哈希、管理员 ID、CSRF 哈希、创建/最后活动/失效/撤销时间 |
| `request_limits` | 限流作用域、来源摘要/账号键、时间窗、计数、阻断截止 |
| `categories` | slug 唯一、中文名称、排序、启用状态 |
| `products` | ID、课程绑定、展示字段、分类、政策、状态、销售检查快照；一课程最多一商品 |
| `orders` | 商品、店铺渠道组合唯一订单号、金额、状态、备注、创建者 |
| `code_batches` | 商品、数量、用途、幂等键、政策快照、创建者 |
| `access_codes`（扩展） | 批次/商品/订单、哈希、编号、政策快照、作废原因/时间、替代码关系 |
| `entitlements` | 课程/商品/订单/原始码、固定交付版本、政策快照、到期/撤销时间；每码最多一权益 |
| `recovery_credentials` | 权益、学习凭证哈希、创建/撤销时间；每权益最多一项未撤销凭证 |
| `sessions`（扩展） | 权益 ID、原始码 ID（可空）、CSRF 哈希、撤销时间；沿用旧 session 哈希结构 |
| `entitlement_progress` | 主键 `(entitlement_id, course_id, chapter_number)`；completed、更新时间 |
| `admin_events` | 操作者、对象 ID、动作、原因、脱敏变化、结果、请求关联 ID |

本批章节序号保持现有含义，并明确禁止更新正文或重排。M3 引入稳定章节 ID 时，将旧序号按原版本映射；不能按新顺序迁移。旧 `progress` 保留兼容和迁移证据，不直接清空。

迁移必须在维护窗口对副本验证并先备份：

1. 标记既有六表为基线，不覆盖它们；新字段保持旧记录可读。
2. 每门既有课程建立草稿状态商品，映射已有分类名称；商品政策必须管理员填写。
3. 每个旧会话创建一份 `legacy` 权益，复制该会话进度，访问截止时间先保留原 `expires_at`；不凭空增加商业时长。
4. 已过期旧会话也保留进度供售后核验，不自动变为有效授权。旧会话之间不能因同课程就合并。
5. 旧已使用码没有可靠的码→会话关联，标记“需核验”，不按兑换时间猜测。旧未使用码在补齐商品政策之前不继续兑付，并在旧码核验页提示管理员必须处理的记录。
6. 恢复/延长旧权益须经店铺核验，记录原期限与新政策；未售的内部测试数据也须明确标记用途，不能假定全为测试。

不得在迁移后遗留绕过商品政策/权益撤销的旧授权路由。所有 `/learn` 正文、PDF、素材和进度操作统一检查权益、会话和课程 ID。

审计规则：成功的发码、补发、退款标记、权益撤销与对应审计在同一业务事务提交；认证/兑换拒绝记录在失败事务结束后独立提交，避免因抛异常而把拒绝日志一起回滚。

## 9. 文件与路由边界

拟创建：`course_platform/admin/auth.py`、`admin/security.py`、`admin/routes/`；`operations/products.py`、`orders.py`、`codes.py`；`delivery/entitlements.py`、`recovery.py`、`progress.py`；`audit.py`、`migrations/`；`templates/admin/`、`static/admin/`。

拟修改：`app.py`（应用组合/路由拆分）、`database.py`（连接与迁移入口）、`access.py`（兼容委托）、`settings.py`（管理员与限流配置）、`cli.py`（部署初始化）、`content.py`（章节素材清单校验）、公开详情/帮助/学习模板、`pyproject.toml`（依赖及模板/静态包资源）、`.env.example` 与操作手册。

主要页面与动作：

| 路径 | 行为 |
| --- | --- |
| `GET/POST /admin/login`，`POST /admin/logout` | 管理员会话 |
| `GET /admin` | 实际待办和最近操作；不存在的数据不伪造 |
| `GET /admin/products`，`GET/POST /admin/products/new` | 列表/创建商品草稿 |
| `GET/POST /admin/categories` | 分类创建、排序、启用/停用 |
| `GET/POST /admin/products/{id}` | 修改商品信息，带修订号检查 |
| `POST /admin/products/{id}/activate`，`pause` | 完成销售检查/暂停销售 |
| `GET /admin/orders`，`GET/POST /admin/orders/new`，`GET /admin/orders/{id}` | 手工订单 |
| `POST /admin/orders/{id}/issue`，`confirm-delivery`，`refund-record` | 发码、确认发货、店铺退款标记 |
| `GET /admin/code-batches`，`GET/POST /admin/code-batches/new`，`GET /admin/code-batches/{id}` | 批次创建、一次明文响应、历史状态 |
| `POST /admin/codes/{id}/revoke`，`replace` | 作废/补发未使用码 |
| `GET /admin/entitlements/{id}`，`POST .../reset-credential`，`revoke` | 权益与售后 |
| `GET /admin/audit`，`GET/POST /admin/account/password` | 审计/修改自身密码 |
| `GET /admin/legacy-codes`，`POST /admin/legacy-codes/{id}/resolve` | 旧码用途/商品政策核验，不推测已兑换会话归属 |
| `GET/POST /access/restore` | 买家凭证恢复 |
| `POST /learn/{slug}/chapters/{number}/progress` | 无 JS 的完成状态表单，检查买家会话和 CSRF |
| `GET /learn/{slug}/downloads/course.zip` | 仅对政策允许且既有 ZIP 已检查的有效权益提供下载 |

真实 URL 采用上述统一前缀，不因菜单名称更换服务端数据职责。修改表单包含修订号，两个标签页编辑冲突返回 409 和重新载入入口，不能静默覆盖。

后台 CSV 来自结果页当前内存中的数据，不提供可反复取回明文的历史下载地址。所有对象 ID 在服务端查权限和关联关系，不能仅靠前端隐藏操作按钮。

管理密码修改须校验当前密码；修改成功撤销该管理员所有旧会话并重新登录。Cookie 作用域：管理 CSRF Cookie 为 `/admin`、SameSite=Strict；买家每课程 CSRF Cookie 为 `/`、SameSite=Lax，供 `/learn` 表单和 `/api/progress` 使用，两者均生产 Secure。CSRF Cookie 中的 token 不是登录凭证，单独持有不能授权。

所有授权下载都检查权益政策：PDF/ZIP 的文件存在不等于该买家可下载。时间存储为 UTC，管理页默认以 Asia/Shanghai 展示；输入日期注明时区，领取截止时间与学习截止时间分开显示。

## 10. 错误与恢复

- 字段错误：保留非敏感表单值，显示字段级原因；密码与凭证不回填。
- 数据库繁忙：限时等待后可理解地返回失败，幂等键供安全重试；不自动重复发码。
- 商品内容变化：检查失效、暂停新发码，显示须重新确认的项；既有权益路径仍检查内容安全，发现破坏性文件变更返回明确不可用而不放行。
- 原始码/学习凭证展示响应丢失：没有“找回明文”后门；根据订单作废/重置，旧授权关系可追溯。
- 同一退款/补发请求重复提交：返回已完成结果，不能产生另一份权益。
- 迁移失败：不自动删除/重建数据库；停止启动并提示使用迁移前副本。回退旧程序前先恢复兼容副本，不能假设旧程序可写新库。
- 网页错误显示业务说明和关联 ID；详细 traceback 仅留脱敏服务日志。

## 11. 验收标准

第一批单独可测试，不依赖真实模型账户。最低验收：

1. 匿名、买家 Cookie、过期/已退出管理员均不能读取后台或发码。
2. 无/错 CSRF、超大表单、非法计数、篡改商品/课程关系被拒绝；恶意文案被转义。
3. 一次生成 1 码和 200 码可用；0、201、布尔/小数输入拒绝；重复幂等提交只产生一批。
4. SQL/日志/生成产物目录没有原始码；明文仅出现在一次响应；CSV 备注/标题不触发表格公式。
5. 同码两个并发兑换只有一次成功；错误码、过期、作废和跨课程码都不能授权；拒绝日志确实提交。
6. 政策以发码时快照为准；领取期限与学习期限计算独立；无固定到期政策只在经营者明确选中时出现。
7. 一个权益完成章节后，用学习凭证换设备/会话到期再恢复仍能看到相同进度；买家有可点击完成按钮。
8. 学习凭证重置后旧凭证和旧设备会话全部失效，进度保留；撤销权益后的正文、PDF、素材、进度 API、恢复入口都不能访问。
9. 暂停销售停止新发码；已发码仍可在领取期内兑换，既有权益可继续学习。
10. 店铺+渠道+订单号去重；退款标记/补发不重复授权；未关联批次与已绑定订单展示准确。
11. 旧数据库副本迁移保留全部课程/码/进度，旧会话不被合并；需核验旧码清单可处理；新授权检查不存在旧路由旁路。
12. 错误注入后业务结果与审计一致；回滚后的拒绝审计不丢失。
13. 手机试学只能请求白名单内的试学素材，不能取得付费素材或私有路径。
14. 构建 wheel 并在临时环境安装后，管理/公共模板与静态资源可加载；不会因导入 app 就修改生产库。
15. 浏览器完整流程：初始化账号→登录→确认现有课程商品→登记订单→发码并复制文案→买家兑换→保存凭证→完成章节→新设备恢复→后台重置/撤销；过程中日常业务无需终端。

测试按域分为管理员身份、商品政策、订单/批次、权益恢复、旧数据迁移、公共交付与浏览器流程；实际新增测试数由有效失败场景决定，不追求堆数量。

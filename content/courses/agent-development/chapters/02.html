第 2 章 · 方法设计

Prompt 与结构化输出：让模型稳定工作

本章目标：把模糊需求拆成角色、输入、约束、输出和验收标准。

1. 从“写得像人”到“可验证”

好的 Prompt 不只是语气自然，而是让输入边界和输出契约清楚。先写任务，再写不可违反的规则，最后给出一个可检查的结果格式。

2. 结构化输出

JSON、枚举和固定字段能够减少下游解析成本。字段名、类型、是否必填以及失败时的行为都应提前约定。

{"summary":"...","risks":["..."],"confidence":0.0}

3. 约束与示例

示例适合说明风格和边界，但不能替代校验器。生产系统应在模型输出后做 JSON 解析、字段检查和长度限制。

4. 练习与总结

将“分析客户反馈”改写为一个有输入字段、输出字段和失败策略的任务。可验证的输出，才适合进入 Agent 循环。
